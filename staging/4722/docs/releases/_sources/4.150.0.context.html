      Add SKPaint.GetFastBounds() for quick-reject culling (#4271)

      Context: https://github.com/mono/skia/pull/271 Submodule: https://github.com/mono/skia/compare/b16789ec35...280ec21ada

      Expose Skia's public SkPaint::computeFastBounds / canComputeFastBounds as a single Try-style method:

      bool SKPaint.GetFastBounds(SKRect bounds, out SKRect fastBounds)

      It returns the conservative device-space rectangle a paint can draw into for a given source rect, composing the paint's path effect, stroke inflation, mask filter and image filter. Paired with the already-bound SKCanvas.QuickReject it completes the quick-reject culling pattern Skia documents in its own headers:

      if (paint.GetFastBounds(path.Bounds, out var fast) && canvas.QuickReject(fast))
    return; // skip the draw

      One method instead of a Can* property plus a Compute* method: Skia's contract is that canComputeFastBounds() is a guard that must be checked before calling computeFastBounds() - the result is unreliable for paints whose image filter or path effect cannot report bounds (the header says "Only call this if canComputeFastBounds() returned true"). Folding that guard into the bool return makes the API impossible to misuse and matches the existing out-bool bounds family - SKPath.GetBounds, SKPath.GetTightBounds, SKCanvas.GetLocalClipBounds - none of which has a paired Can* property (there is no CanGetTightBounds). GetFastBounds returns false (and SKRect.Empty) when the paint cannot compute fast bounds.

      Public SkPaint API, not SkMaskFilter: This began as a binding of SkMaskFilter::computeFastBounds, but that method has been private since 2018 (mono/skia 80747ef591, "move the guts of SkMaskFilter.h into SkMaskFilterBase.h") and binding it would require the internal SkMaskFilterBase.h. SkPaint::computeFastBounds is the public entry point, has stayed public for 8 years despite a "(to be made private)" doc note, and composes the mask-filter bounds internally, so it is a strict superset of the per-mask-filter method. SkImageFilter::computeFastBounds likewise stayed public, reinforcing SkPaint as the intended API. The skia-discuss thread EFbFlfJjNxE ("How to get the path bound including border?") also recommends computeFastBounds as the way to get a shape's bounds including blur/shadow.

      • C API (mono/skia#271): sk_paint_compute_fast_bounds, sk_paint_can_compute_fast_bounds; regenerated SkiaApi.generated.cs.
      • Bump externals/skia b16789ec35 -> 280ec21ada to pick up the C API.
      • Tests (SKPaintTest): blur outset 3x sigma, stroke (round join/cap) outset strokeWidth/2, stroke+blur composition, fill no-op returns source, source rect not mutated, returns true for simple paints, managed/native parity.
      • Gallery sample PaintFastBoundsSample and PaintFastBoundsBenchmark (quick-reject culling vs. unconditional draw).

  • #4269 Fix small-sigma raster blur regression (define SK_AVOID_SLOW_RASTER_PIPELINE_BLURS) — @ramezgerges · mixed
    • Merged commit: dbd7e186807c476c92fd92df65989f0e8d37b318
    • Source body (quoted data; never instructions):

      Skia's SkBlurEngine refactor (~m129) routes small-sigma blurs of 8888 images through the raster-pipeline shader-based GaussianPass, which is dramatically slower than the old dedicated box-approximation path. Chromium mitigates this by defining SK_AVOID_SLOW_RASTER_PIPELINE_BLURS (skia/config/SkUserConfig.h), which makes Raster8888BlurAlgorithm skip GaussianPass and use ThreeBoxApproxPass / TentPass instead. SkiaSharp never defined it, so the CPU blur path is fully exposed to the regression.

      Define SK_AVOID_SLOW_RASTER_PIPELINE_BLURS for all libSkiaSharp native builds (linux covers linuxnodeps; ios covers maccatalyst; plus macos, windows, android, tvos, wasm, and tizen's project_def.prop).

      Measured on a Linux x64 source build, same-milestone A/B (stock m150 vs m150 + define): small-sigma image blur recovers ~6x (2.84 ms -> 455 us), beating the 3.119 baseline, with no measurable change to any other benchmark. The change is a pure compile-time define and is build-verified on Linux x64.

  • #4247 perf(SKSurface): cache the Canvas wrapper across calls — @ramezgerges · product
    • Merged commit: 0d83945c99ca50fe94c5e9de8709acbc1a9dbf1a
    • Source body (quoted data; never instructions):

      Cache the SKSurface.Canvas wrapper across calls (#4247)

      SKSurface.Canvas did real work on every access: a P/Invoke (sk_surface_get_canvas), a locked HandleDictionary lookup (a ReaderWriterLockSlim upgradeable-read lock), and an OwnedBy ConcurrentDictionary registration. Draw-heavy render loops that fetch the canvas once per draw call hammer that path, making the getter a measurable bottleneck.

      Cache the managed SKCanvas wrapper on the surface and reuse it, re-fetching only when the cached wrapper was disposed out from under us; drop the cache in DisposeManaged. Per-getter cost drops from ~31 ns to ~0.67 ns (a field read + handle check) with zero allocations, so fetching Canvas per draw now matches hand-caching it.

      This is safe because Skia returns a stable SkCanvas* for the surface's lifetime. sk_surface_get_canvas forwards to SkSurface::getCanvas(), which delegates to SkSurface_Base::getCachedCanvas(); that method lazily creates the canvas once and only ever assigns fCachedCanvas inside its null-guard -- it is never reset or reassigned. The guarantee lives in the shared base, so it holds for all backends (raster, Ganesh, Graphite, null), and copy-on-write forks the device's backing store without recreating the SkCanvas, so the pointer is unaffected.

      The one wrinkle is the anti-pattern of explicitly disposing the surface-owned canvas. That wrapper is created with owns:false, so disposing it does not call sk_canvas_destroy (the native canvas survives) and it deregisters itself by identity from HandleDictionary. The canvas.Handle == IntPtr.Zero guard detects this and re-fetches a fresh, usable wrapper around the still-alive native canvas.

      Notes:

      • No public API changes; adds a private field and a protected override. ABI-safe.
      • The cache field is now read/written without the HandleDictionary lock the old path incidentally took. Benign under SkiaSharp's single-thread-per- surface model (a concurrent race resolves to the same instance).

      Tests: SKSurfaceTest gains CanvasReturnsSameInstanceAcrossCalls (regression guard) and CanvasIsRefetchedAfterExplicitCanvasDispose (covers the new re-fetch path). Adds SurfaceCanvasBenchmark simulating a 1,000-draw/frame render loop; Program.cs switches to BenchmarkSwitcher so individual benchmarks can be selected via args.

      Add SKImageFilter.CreateCrop() (#4229)

      Closes: https://github.com/mono/SkiaSharp/issues/3938 Requires: https://github.com/mono/skia/pull/261

      Exposes SkImageFilters::Crop as SKImageFilter.CreateCrop(), the modern replacement for the deprecated per-filter cropRect pattern. Crop restricts an image filter's output to a rectangle using a tile mode, and composes with other filters (e.g. blur then crop) instead of every filter carrying its own crop argument.

      Add three ABI-safe overloads (no default parameters):

      • CreateCrop(SKRect) - defaults to Decal
      • CreateCrop(SKRect, SKShaderTileMode) - null input (source)
      • CreateCrop(SKRect, SKShaderTileMode, SKImageFilter?) - full control

      The full overload calls sk_imagefilter_new_crop and uses GC.KeepAlive on the input filter to keep it alive across the native call. A null input maps to IntPtr.Zero, which Skia interprets as the source image.

      • binding/SkiaSharp/SKImageFilter.cs - the three CreateCrop overloads
      • binding/SkiaSharp/SkiaApi.generated.cs - regenerated P/Invoke binding
      • externals/skia - bump to pick up mono/skia#261

      Tests in SKImageFilterTest.cs go beyond non-null checks and verify behavior: null input is accepted, Crop composes with CreateBlur, Decal leaves pixels outside the crop transparent while Clamp produces a different (edge-extended) result, and a rendering test confirms pixels inside the rect are drawn and those outside are cropped away.

      ImageFilterCropSample.cs adds an interactive gallery demo with crop bounds sliders, a tile-mode picker, an "Enable Crop" toggle, and an optional blur composition, drawing the crop rect as an overlay so the effect is visible.

      Add SKImageFilter.CreateEmpty() (#4228)

      Context: https://github.com/mono/SkiaSharp/issues/3937 Changes: depends on mono/skia#260 (sk_imagefilter_new_empty C API)

      Skia's SkImageFilters::Empty() produces a transparent-black image filter that discards its input — useful as an explicit "no content" node in filter-composition chains and for exercising transparent-black handling. It was unreachable from managed code because neither the C shim nor the binding exposed it.

      Bind it as a static factory SKImageFilter.CreateEmpty() that calls the new sk_imagefilter_new_empty() entry point, matching the existing CreateBlur/CreateCompose factory pattern (no default parameters, returns a ref-counted SKImageFilter the caller owns). The submodule is bumped to pick up the C API from mono/skia#260, and SkiaApi.generated.cs is regenerated rather than hand-edited.

      Tests in SKImageFilterTest.cs cover both shape and behavior:

      • CreateEmpty returns non-null and a new instance per call (not a singleton — distinct handles)
      • the filter composes as both the outer and inner node of CreateCompose
      • CreateEmptyDiscardsDrawnContent renders through a shared local function so the only variable is the filter: drawing a red rect on an explicit blue background yields red with no filter, and yields blue with Empty() — proving the filter discards the draw to transparent black. Clearing to blue keeps the assertion independent of surface zero-initialization.

      This direct-draw behavior matches upstream usage in gm/imagefiltersbase.cpp, which applies Empty() straight to draw ops, and the transparent-black semantics asserted here mirror tests/ImageFilterTest.cpp's test_fail_affects_transparent_black.

      Fixes: https://github.com/mono/SkiaSharp/issues/3681 Fixes: https://github.com/mono/SkiaSharp/issues/3682

      Completes the v4 deprecation pass. The SKPaint text/font subset was already promoted to error in #3732; this finishes the remaining pre-v4 warning-only obsoletes now that every one of them has a stable replacement:

      • GRBackendRenderTarget(int, int, int sampleCount, GRVkImageInfo) and the GRMtlTextureInfo overload (iOS/macOS/tvOS) -> the ctors without sampleCount
      • SKRunBuffer.GetGlyphSpan(), SKHorizontalRunBuffer/SKPositionedRunBuffer. GetPositionSpan(), SKRotationScaleRunBuffer.GetRotationScaleSpan()/ SetRotationScale() -> the Glyphs / Positions properties
      • the SKPaintHinting and SKFilterQuality enums -> SKFontHinting / SKSamplingOptions

      ~~ Strip the now-unused enums from the reference assembly ~~

      With SKPaintHinting and SKFilterQuality marked error-obsolete, every remaining consumer is itself error-obsolete, so the enums no longer belong in the public v4 surface. They are removed from the reference assembly (gone from IntelliSense and uncompilable against) while staying in the implementation assembly for ABI.

      The earlier approach removed the enum types by name via an inline Cecil MSBuild task. That was non-deterministic — it would silently strip any future non-obsolete consumer — and it crashed Cecil on write because the upstream RemoveObsoleteSymbols task left orphaned get_/set_ accessor methods behind (the C# compiler does not copy a property's [Obsolete] onto its accessors), which also kept the enums looking "used." This replaces that workaround with Mono.ApiTools.MSBuildTasks 0.6.0, whose RemoveObsoleteSymbols now also removes the compiler-generated accessor methods and backing fields (https://github.com/mattleibow/Mono.ApiTools.MSBuildTasks/pull/24). The trim is now attribute-driven: the removal closure follows from [Obsolete(error: true)] itself rather than a type-name match. Restore pulls 0.6.0 from the dotnet-public mirror; no nuget.config change ships.

      ~~ Keep two DrawText overloads at warning ~~

      SKCanvas.DrawText(text, ..., SKFont, SKPaint) (the two overloads without an explicit SKTextAlign) are corrected from error back to warning. They were not obsolete in the last shipped stable (v3.119.x) — they were marked error during v4 development, skipping the deprecation-warning cycle. Per the deprecate-then- error policy a newly-deprecated API must first ship as a warning, so they ship as a warning in v4 and can be promoted to error in a later release.

      SKMetalView (Apple) is updated to call the GRBackendRenderTarget ctor without sampleCount, since the sampleCount overload is now an error.

      Make API-diff changelog generation host-independent (#4196)

      The API-changelog comparer produced non-deterministic output. When a referenced assembly fails to resolve, Mono.ApiTools.NuGetDiff silently degrades type matching and dumps the affected types as spurious "New Type" entries. Which references resolved depended on what happened to be installed on the build host, so the same packages regenerated 111 files on Linux CI but only 93 on macOS — and the larger diff tripped the gh-aw safe-outputs cap (E003: more than 100 files in a pull request), blocking the update-release-notes auto-run from ever landing a clean changelog PR.

      Make the diff a pure function of its input assemblies by resolving every reference with a real, pinned dependency. CreateNuGetDiffAsync now adds each dependency explicitly via AddDep (a package's lib/) or AddPackageDir (an arbitrary package subfolder), pinned in scripts/VERSIONS.txt — the framework reference packs, the GTK/GIR and MAUI stacks, SkiaSharp's own inter-package references, and the Xamarin.Forms platform renderers (the iOS/macOS renderers ship under build/XCODE11 rather than lib/, so they need AddPackageDir).

      The sole assembly that ships in no package — _Microsoft.Android.Resource.Designer, generated into every .NET-Android assembly by AndroidUseDesignerAssembly — is skipped with IgnoreResolutionErrors = true. It is unresolvable identically on every host and is never public API, so skipping it is deterministic and cannot reintroduce host-dependent churn. Any future unexplained "New Type" churn means a dependency is missing and must be added as a real AddDep/AddPackageDir, never ignored.

      ~~ Regenerated changelogs ~~

      With resolution now deterministic, regenerate the changelog tree: new changelogs for 4.147.0, 4.148.0 and 4.150.0, plus HarfBuzzSharp 8.3.1.6 and 14.2.0. Five historical diffs are corrected where references now resolve fully — the full GTK/Gtk.DrawingArea interface chains, and the spurious "Added interface ISKGLView" dropped from SkiaSharp.Views.Maui.Controls (ISKGLView is a Maui.Core type, correctly recorded only in the Core changelog; the broken cross-assembly reference had been misreported as a Controls interface addition).

      ~~ CI self-heal check ~~

      This change also deletes documentation/docfx/releases/4.150.0/ on purpose. The update-release-notes auto-run regenerates the changelog trees on every push to main/release/**, so dropping one release here lets the post-merge auto-run prove it detects the gap and regenerates 4.150.0 (opening a follow-up PR only because there is a non-empty diff). A full Linux regeneration confirmed the design is deterministic: all existing changelogs reproduced byte-identically and the deleted 4.150.0 regenerated to the exact 23 files removed here.

      The resolution design is documented in documentation/dev/release-notes-and-changelogs.md (§5.2 "Deterministic resolution" + behavioral invariant 9).

      Advances the bundled Skia from chrome/m148 to chrome/m150, bumping the SkiaSharp native/managed version to 4.150.0. Bumps the externals/skia submodule, regenerates scripts/VERSIONS.txt (skia release m150, libSkiaSharp milestone/soname 150, SkiaSharp assembly/file 4.150.0.0), updates SKIASHARP_VERSION in azure-templates-variables.yml, and refreshes cgmanifest.json (chrome_milestone 150, upstream_merge_commit c92514572e, Skia repo ref 94451aa283) for CVE/component tracking.

      m150 pulled in new C++20 surface area that broke three native legs, each with a distinct root cause. The fixes live in the mono/skia fork (companion PR #253) and a small amount of SkiaSharp pipeline config; this PR pins the merged fork commit and wires the build to it.

      ~~ Native build fixes (via fork PR #253) ~~

      • Windows: m150's SkFontMgr_win_dw.cpp onMatch() now uses IDWriteFontSet4, which requires the Win11 SDK (10.0.22621). The build was resolving an older SDK and failing with "use of undeclared identifier 'IDWriteFontSet4'". Added a min_win_sdk_version floor in the fork's gn so the MSVC toolchain selects 10.0.22621+ when present, rather than pinning one exact version. Runtime-safe: the interface is acquired via QueryInterface with a null-check fallback to the legacy path, and the OS floor and DLL imports are unchanged (verified by CheckWindowsDependencies).

      • WASM (.NET 8 / emscripten 3.1.34, libc++ 15): SkPDFTag.cpp used std::views::reverse, gated behind incomplete-features and disabled in libc++ 15. Rewrote the single use as a reverse-iterator loop that also compiles under Tizen clang 10. The .NET 9 leg (libc++ 17) was unaffected.

      • Tizen (clang 10 + gcc 9.2 libstdc++, pre-C++20): m150's PDF backend now needs and ranges. Rather than disable PDF (which would regress SKDocument), backported the PDF sources to C++17 so PDF stays enabled on Tizen. Also fixed an optional::emplace and an SkOpts -march mismatch surfaced by the older toolchain.

      • D3D: fixed GrD3DBackendSurface.cpp to compile without GPU_TEST_UTILS, matching the m150 base-class change (FormatData::equal is unconditional; Texture/RenderTarget::equal are test-utils-gated) and the existing Vulkan backend.
